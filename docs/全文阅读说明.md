# AIdea 3.6.1.9：全文文字阅读

安装 AIdea-3.6.1.9-fulltext.xpi，完全退出并重新打开 Zotero。建议用新对话检查，避免先前错误回答继续影响上下文。

## 本次行为

- PDF 对话每轮发送该文件全部已提取文字；提到 Figure 3、指定页码或继续追问，不再把提供的文字缩成图注或某几页。
- 先为 PDF 全文文字预留容量，剩余容量再放入历史对话。引用多篇 PDF 时分别预留各篇所需容量。
- 容量确实不足时明确报错，显示估计所需 token 和当前材料容量，不调用主问答模型，不悄悄退回摘录。检查模型高级设置的上下文上限时，应使用供应商实际支持的值；不要随意调高。也可减少同时引用的文献或附件。
- 删除最后一轮预算检查中静默删减 PDF 正文的行为。若最终仍超限，先减少历史或记忆；无法保留全部 PDF 文字时停止发送。
- 扫把旁的一键扫描及图片监测交互保持不变。扫描图片作为普通参考上下文加入，与文字不设固定证据优先级；按问题和证据本身回答。
- 回答下方明确区分“全文文字已提供”“提取不完整”“仅文字摘录”。旧对话中的摘录记录不会被改成全文。

全文指该 PDF 文件中已提取的文字，不等同于整篇论文所有图片，也不包含未添加的单独补充文件。没有可提取文字的扫描版 PDF 需先进行文字识别。若提取状态不完整，会明确标记，不保证原文件内每个内容都已成功提取。

全文会增加输入 token；实际费用和缓存优惠取决于所用接口。全文上下文能减少缺失原文的问题，不能保证模型从此不会误读或产生幻觉。

## 验证

- 用一篇79页、约29万字符的真实论文文字测试图号问题、页码问题及追问，全部文字块逐一保留原文。
- 测试真实请求准备函数：含扫描图、不含扫描图、长历史、不同大小的多篇 PDF、容量不足及最后阶段超限。
- 图片发送结构、扫描包装对象兼容及 Zotero 自带 PDF 引擎转图检查通过；扫描反馈和20种界面布局检查通过。
